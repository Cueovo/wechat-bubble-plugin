# 阶段 05：安全模式、兼容门控与性能

## 目标

把可工作的文字气泡功能提升为可公开测试的稳定 MVP：未知版本失败关闭、启动异常可恢复、诊断不含聊天内容、滚动性能达标。

## 前置条件

- 阶段 04 已通过。
- 设置和气泡核心已经稳定。
- 所有临时探索 Hook 已从 Release 路径移除。

## 0.4.0 首批实现

- 启动时写入本地哨兵；上一次启动未在稳定窗口内完成时递增连续失败计数，连续 3 次未完成后的下一次启动进入安全模式。
- 微信每次进入前台后，从 `DidBecomeActive` 起使用单调时钟计时；`WillResignActive` 会使本轮计时失效，只有连续稳定 20 秒才清除 pending 和失败计数。安全模式仅影响当前进程，稳定运行或在设置页手动准备恢复后，下次冷启动重新尝试气泡功能。
- 安全模式不安装 `WBTextBubbleStyleHook`，但继续安装插件归纳设置入口；设置页新增“安全与恢复”，诊断新增 `safety` 快照。
- 版本升级为 0.4.0、诊断格式升级为 10、`buildStage=safety`。3 次阈值和 20 秒窗口是故障演练前的初始值，必须经过真机正常强退和模拟中断验证后才能定稿。

### 0.4.0 真机故障演练

1. 正常冷启动并在前台停留至少 20 秒，确认 `safety.launchPending=false`、`incompleteLaunchCount=0`、`active=false`。
2. 在 20 秒内连续结束微信并重启 3 轮；第 4 次启动应显示 `active=true`、气泡 Hook 未安装，但插件归纳和“聊天气泡”设置页仍可打开。
3. 在安全模式设置页点击“安全模式”，确认提示“已准备恢复”；完全结束并重启后应恢复正常气泡。
4. 单次快速强退后让下一次启动稳定运行 20 秒，确认计数归零，不会持续累积为安全模式。

## 实施步骤

### 版本与能力门控

1. 将微信 8.0.60 精确 build 标记为首个 `Supported`。
2. 其他版本默认为 `Unknown`，不注册气泡 Hook。
3. 即使版本匹配，也必须检查候选类、方法签名和定位能力。
4. 任一必要能力缺失时只禁用 BubbleFeature，设置和诊断仍可访问。

### 安全模式

1. 初始化前写入本地启动哨兵。
2. 微信稳定进入前台并经过验证窗口后标记本次启动成功。
3. 只有连续多次未完成才进入安全模式，避免正常强制结束被误判。
4. 安全模式不注册气泡 Hook，但保留关闭功能、清理状态和诊断入口。
5. 阈值必须通过真机故障演练确定，不直接照搬社区项目数值。

### 诊断

允许：插件、iOS、设备、Dopamine/loader、微信版本、适配器、能力、安全模式和内部错误码。

禁止：微信号、联系人、会话名称、消息正文、媒体路径、数据库路径、Cookie、Token、Keychain 和完整视图树。

### 性能

1. 缓存已识别的局部气泡视图。
2. 布局热路径禁止 I/O、网络、JSON 和逐消息日志。
3. 预计算主题对象，避免滚动中创建图片和重复 layer。
4. 比较插件关闭/开启的 Time Profiler、Core Animation 和 Allocations 结果。

## 故障演练

- 候选类不存在。
- 方法签名不匹配。
- 微信版本改为 Unknown。
- 偏好数据损坏。
- 初始化中断多次触发安全模式。
- 与另一个气泡 UI Tweak 共存并显示冲突提示。
- 设置入口失效但气泡功能能够安全关闭。

- [x] 微信 8.0.60 精确 build 才默认启用。
- [x] Unknown/能力缺失时不注册气泡 Hook。
- [ ] 故障演练可进入安全模式并在微信内恢复。
- [ ] 正常强制结束微信不会持续累积为错误启动。
- [ ] 诊断导出经人工检查无账号和聊天数据。
